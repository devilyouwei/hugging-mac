## Preserved behavior

The bundle includes the decision checkpoint and all nine task adapters: span, router, relation, NER, span sets, evidence, domain, factcheck and feedback_df. It preserves original FP32 tensors, LoRA projections, heads, thresholds and public `system_one(state, questions, model=None)` / `predict(state, questions)` structures. No adapters are filtered, no LoRA matrices are merged and no quantization is applied.

Original rendering, tokenizer, routing, window aggregation and span decoder remain in use. Source files are copied unchanged; the loader isolates sibling imports in a private Python package. Host processing uses upstream Python code. All neural operations execute through Core AI; the SDK does not run a PyTorch neural model as a fallback.

Five small architecture graphs share original external weight storage. The active component's exact tensors are cached as immutable Core AI inputs. One component is resident at a time. Graphs plus metadata occupy about 3.6 MiB; the original ten checkpoint files are also required and are not embedded or omitted. Locally, hardlinks avoid duplicating checkpoint storage where supported.

| Graph | Components |
| --- | --- |
| decision | decision |
| span-r128-a256-all | span, span sets, evidence |
| span-r256-a512-all | relation, NER |
| router-r128-a256-all | domain, factcheck, feedback |
| router-r256-a512-all | shared router |

LoRA ranks come from the actual safetensors headers. Weight-input schemas account for 231 decision tensors, 572 per span component and 567 per router component, including shared backbone tensors.

## Dynamic inputs and limits

Batch, sequence, question, option, word-unit and label axes remain dynamic. The graph sequence bound is 32768. Original defaults remain unchanged: decision context 32768, schema windows 8192 with 512 overlap, and evidence windows 32768. There is no new fixed 128/1024/2048-token cap.

Native inference was measured at 1024 and 2048 decision tokens. **A full 32768-token execution and large-batch performance were not tested.** The symbolic range is not a maximum-length memory/performance guarantee. CPU on this 8 GB Apple Silicon Mac is the verification target; GPU, ANE, Swift preprocessing and iOS are not claimed as tested.

## Evaluation contract and cases

The oracle uses the original PyTorch networks and original adapter loader, holding one adapter at a time to reduce memory use. Source revision, full snapshot hashes, converted inventory and source/case digests are checked before reusing references.

Raw outputs are compared for every component. Complete SDK responses are compared recursively: fields, selected labels, counts, offsets and usage must match; floating-point values use `atol=0.02, rtol=0.02`. All observed errors were much smaller than this threshold. No tolerance was relaxed during evaluation.

The 20 cases cover multilingual choice; structured state and multiple choice/noul questions; single option; empty questions; invalid question behavior; exact 1024/2048-token inputs; domain/factcheck/feedback routers; shared router choice/set; generic and toxic spans; NER; relations; PII; unsupported claims; evidence; and mixed decision/span heads. The SDK validation script reruns packaged original-reference cases and requires all ten component routes to be exercised.

## Earlier runtime experiment

An earlier mutable-state build passed several raw component checks but reached about 5.9 GB process footprint and caused memory pressure. Those runs were stopped and recorded as interrupted, not validated. The final bundle replaces mutable weight state with cached immutable inputs, preserving the same weights and mathematics. Only the final bundle and complete native report above are approved by this evaluation.
