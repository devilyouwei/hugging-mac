# 产品边界与设计原则

状态：`Proposed`

## 愿景

让开发者在一台 Apple Silicon Mac 上，用一致的方式发现、下载、加载、运行、评估和训练不同年代、
不同模态、不同运行时的模型，同时保留对底层性能和资源行为的观察能力。

## 范围

仓库覆盖：

- 经典模型：CNN、RNN/LSTM/GRU、Transformer encoder、YOLO、CLIP 等；
- 现代模型：LLM、VLM，以及后续可能加入的音频和扩散模型；
- 推理、交互 Demo、评估、微调/训练、导出与性能分析；
- PyTorch MPS、MLX、Core ML，必要时兼容 ONNX Runtime CPU；
- 模型权重、数据集、运行结果和本地缓存的可控管理。

首阶段不追求：

- 分布式集群训练；
- 云端模型托管平台；
- 为所有框架提供完全相同的底层算子；
- 在一个进程内同时挤入任意数量的大模型。

## 核心原则

1. **SDK 优先**：任何模型先成为可导入的 SDK 能力，Demo 只是 SDK 的一个消费者。
2. **契约稳定，适配器可换**：业务依赖抽象和 schema，不依赖 PyTorch、MLX 或 Core ML 对象。
3. **实例隔离**：模型定义、模型资源与运行实例分开；同一定义可创建多个实例。
4. **显式生命周期**：加载、预热、推理、卸载和失败都必须可观察。
5. **资源有预算**：内存、并发、缓存和设备选择由资源管理器协调。
6. **本地优先**：默认数据不离开设备，默认不启动遥测。
7. **可复现**：配置、代码版本、模型摘要、数据摘要和硬件信息共同构成一次运行记录。
8. **能力渐进**：先形成最小纵向闭环，再扩展模型数量。

## 成功标准

- 加入一个新模型不需要修改业务核心；
- Demo、评估和训练能复用同一个模型声明与资源解析机制；
- 模型失败不会让 API 主进程失去服务能力；
- 相同配置与资源摘要可重建一次实验；
- 用户能知道当前加载了什么、占用多少资源、为何选择某个 runtime。
